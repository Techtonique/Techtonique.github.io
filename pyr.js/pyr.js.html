pyr.jsv0.1.0

Python and R in HTML pages, with one script tag. No server, no build step, no install.

pyr.js finds Python and R code in a page and runs it in the visitor's browser. Pyodide (Python) and webR (R), both compiled to WebAssembly, do the heavy lifting; pyr.js connects them to your HTML. It is a single file of about 460 lines, MIT-licensed, with no telemetry.

Source code, examples and issues: github.com/Techtonique/pyr.js.

<script src="https://cdn.jsdelivr.net/gh/Techtonique/pyr.js@v0.1.0/pyr.js"></script>

<p id="count">count = 0</p>
<button py-click="add_one()" py-out="count">Add</button>

<script type="text/python">
count = 0

def add_one():
    global count
    count += 1
    return f"count = {count}"
</script>

Save this as an .html file and double-click it. The first visit downloads Python (several MB, cached by the browser afterwards).

Getting started

install From a CDN 
<script src="https://cdn.jsdelivr.net/gh/Techtonique/pyr.js@v0.1.0/pyr.js"
        integrity="sha384-HASH" crossorigin="anonymous"></script>

Tagged versions on jsDelivr never change, so you can pin one with an integrity hash, computed with openssl dgst -sha384 -binary pyr.js | openssl base64 -A. Replace .js with .min.js for a minified copy.

install On your own site

Copy pyr.js next to your pages and load it with <script src="pyr.js"></script>. A copy on the same site as the pages enables the shared mode, where Python survives page reloads (see Where code runs).

install From disk

Put pyr.js next to an HTML file and open the file directly (double-click). This works without any server. Pages opened this way can't read other local files, so keep Python and R code inside the page.

Code blocks

element <script type="text/python">

Python code, inline or from a file with src="app.py" (served pages only).

Blocks run in page order and share variables with the other Python blocks of the page. What a block prints, and the value of its last line (as in Jupyter), appear right after the block. Packages it imports (numpy, pandas, ...) are downloaded and loaded automatically.

<script type="text/python">
import statistics
xs = [1, 2, 3, 4]
statistics.mean(xs)        # shown as 2.5
</script>
element <script type="text/r">

R code, inline or from a file with src="analysis.R" (served pages only).

Blocks run in page order and share variables with the other R blocks of the page. Output is printed like the R console, and plots appear as images right after the block. Install extra packages with webr::install("name"); only packages built for webR are available.

<script type="text/r">
fit <- lm(mpg ~ wt, data = mtcars)
summary(fit)
plot(mtcars$wt, mtcars$mpg)
</script>

Attributes

attribute py-<event>="code"

Runs Python when the DOM event fires on this element: py-click, py-input, py-change, py-submit, py-keyup, ... any event name works. The code is usually a call to a function defined in a Python block. For py-submit, the form's default submission is prevented.

<button py-click="add_one()" py-out="count">Add</button>
<select py-change="pick(_value)" py-out="choice">...</select>
attribute r-<event>="code"

The same for R: r-click, r-input, r-change, ...

<input type="range" min="10" max="500" r-input="hist(rnorm(as.numeric(.value)))" r-out="plot">
attribute py-ready="code", r-ready="code"

Runs once, as soon as the engines are ready and the code blocks have run. Typically used to draw a chart when the page opens. Can be combined with an event on the same element:

<input type="range" py-ready="walk(_value)" py-input="walk(_value)" py-then="drawWalk" py-out="chart">
attribute py-out="id", r-out="id"

Where the result goes: the element with this id. Its content is replaced by the text output of the code (what it prints, otherwise its value), by R plots, or by the error message. Text is always inserted as text, never as HTML. Without py-out / r-out, errors appear in red next to the element.

attribute py-then="fn", r-then="fn"

Passes the result to your JavaScript function as data instead of displaying it, for example to draw a chart. The function is looked up on window (dotted names such as charts.draw work) and called as fn(data, element, event), where element is the py-out / r-out element if there is one, otherwise the element itself. See Data conversion.

<script>
  function draw(rows, el) {
    el.replaceChildren(Plot.dot(rows, { x: "wt", y: "mpg" }).plot());
  }
</script>
<div r-ready="mtcars[, c('wt', 'mpg')]" r-then="draw" r-out="chart"></div>
<div id="chart"></div>
variable _value, .value

The current value of the element that triggered the code (an input, slider or select), as text: _value in Python, .value in R. Convert it as needed, e.g. int(_value) or as.numeric(.value).

Script tag options

option data-watch

Re-runs src files when they change, in the running interpreter, without reloading the page (checked every second). For development, on served pages.

<script src="pyr.js" data-watch></script>
<script type="text/python" src="app.py"></script>
option data-langs="python r"

Starts downloading the listed engines immediately, before the page has finished loading. Without it, pyr.js looks at the page first and loads only the languages it uses.

option data-py-index="url"

Location of a self-hosted Pyodide (its full/ folder). Default: https://cdn.jsdelivr.net/pyodide/v314.0.7/full/.

option data-r-base="url"

Location of a self-hosted webR. Default: https://webr.r-wasm.org/v0.6.1/. Use webR's release archive from GitHub, not the npm package, which targets Node and bundlers.

JavaScript API

function pyr.data(lang, code) → Promise<any>

Runs code (lang is "python" or "r") and resolves with its result converted to JavaScript data. Rejects with an Error holding the Python traceback or R error message. Printed output goes to the browser console.

const rows = await pyr.data("r", "head(mtcars[, c('wt', 'mpg')])");
const total = await pyr.data("python", "sum(range(10))");   // 45
function pyr.exec(lang, code) → Promise<Array>

Runs code and resolves with its raw output items, objects of the form { kind, data }, where kind is "stdout", "stderr", "value" (text) or "image" (an ImageBitmap, for R plots).

function pyr.rerun() → Promise<void>

Runs every code block of the page again, re-reading src files.

variable pyr.version

The version string, e.g. "0.1.0".

event pyr:ready

Dispatched on document once the engines are ready, the code blocks have run and the attributes are active. event.detail.warm is true when every engine was already running (shared mode).

document.addEventListener("pyr:ready", async () => {
  const data = await pyr.data("python", "walk(200)");
});
attribute <html data-pyr="loading|ready|error">

Set by pyr.js on the root element, so CSS can style the page while engines start:

html[data-pyr="loading"] button { opacity: .5; pointer-events: none; }
class .pyr-block, .pyr-output, .pyr-error, .pyr-plot

CSS classes of what pyr.js adds to the page: .pyr-block follows each code block and holds its output, .pyr-output is printed text, .pyr-error an error message, and .pyr-plot an R plot (a canvas drawn at twice its display size, so set e.g. .pyr-plot { width: 504px; max-width: 100%; height: auto; }).

Data conversion

table Python and R values in JavaScript

How results passed with py-then / r-then or pyr.data() are converted:

Python R JavaScript
int, float, str, bool numeric, character, logical vector of length 1 number, string, boolean
dict named list, named vector object
list, tuple, numpy array unnamed list, vector array
pandas DataFrame data frame array of row objects
pandas Series object (label: value)
None NULL, NA null
datetime, date Date, POSIXct, factor string
set Set

In R, a vector of length 1 arrives as a single value, not as an array of one element.

Where code runs

table How the page is opened
How the page is opened Python R
From disk (double-click) On the page On the page, R itself in a worker
Served, pyr.js from a CDN Worker per page Worker per page
Served, pyr.js from the same site Shared worker: other tabs and reloads reuse it Worker per page

In the shared mode, each tab still has its own variables and a reload starts the page fresh; only the running interpreter is reused. Keeping it alive across reloads relies on a recent Chromium feature; other browsers start it again after a reload. R can't be shared, because webR starts a worker of its own, which Chrome doesn't allow inside a shared worker.

Measured locally in Chromium, with the engines already in the browser cache:

Situation Ready in
Python, first start about 3 s
R, first start about 2 to 4 s
Python, another tab or a reload (shared mode) under 0.1 s

Privacy and security

note What leaves the browser

Nothing, as far as pyr.js is concerned: there is no telemetry. The CDNs that serve the engines and packages see the usual request information (IP address, referring site, which files), never your data. Self-host the engines to avoid even that.

note What to keep in mind
  • Code in a page is visible to its visitors: never put secrets (API keys, passwords) in it.
  • py-out / r-out insert text, never HTML. If a py-then / r-then function inserts results as HTML, sanitize them first.
  • Pin a version and use an integrity hash when loading pyr.js from a CDN.
  • Report vulnerabilities privately through GitHub.
